# Проект 2. Cashback Merge

Мини-игра в духе 2048 на поле `4x4`. На поле появляются плитки с кэшбэком,
две одинаковые объединяются в следующую:

```text
1% + 1% = 2%    2% + 2% = 4%    ...    16% + 16% = 32%
```

У игрока ограниченное число ходов, цель — собрать максимальный кэшбэк.

Но у проекта есть второй, продуктовый слой. По итоговой плитке начисляется
награда, и эта награда стоит компании денег. Поэтому максимальную награду
должна получать ограниченная доля игроков — например, не больше `20%`.
Проверяется это симуляцией на тысячах «игроков» до запуска акции.

Задание разбито на три merge request'а. Делай их по очереди.

## Быстрый старт

```bash
./gradlew run     # запустить программу
./gradlew check   # тесты и линтеры — ровно то, что проверяет CI
```

Нужен **JDK 25 или новее**. Gradle ставить не нужно — в проекте лежит `gradlew`,
он скачает нужную версию сам.

## MR1: начальное состояние

Программа загружает настройки из `config/campaign.example.json`, проверяет
размер поля, лимит ходов и spawn-правила, создаёт начальное состояние и выводит
игровое поле в консоль.

На Windows запусти:

```powershell
.\gradlew.bat run
```

Если русские сообщения отображаются некорректно, сначала включи UTF-8 в текущем
окне PowerShell:

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

Затем запускай Gradle-команду в этом же окне PowerShell.

Начальное поле создаётся с seed `42`. При одинаковом конфиге и seed расположение
плиток повторяется. Сейчас на поле создаются две стартовые плитки; уровень обеих
берётся из первого правила `spawnRules`. Выбор уровня плитки с учётом вероятностей
будет добавлен на этапе MR3.

## MR2: ходы и слияния

`MoveEngine` применяет ход к `GameState`. Направление задаётся одним из значений
`MoveDirection`: `UP`, `DOWN`, `LEFT` или `RIGHT`. Метод `applyMove` возвращает
`MoveResult`: `valid()` показывает, изменилось ли поле, а `scoreGained()` — сколько
очков принесли слияния в этом ходе.

Плитки сдвигаются к выбранному краю. Соседние плитки одного уровня объединяются
в следующую; результат слияния не может объединиться повторно в том же ходе.
Если ход не меняет поле, он не расходует лимит и не создаёт плитку. После валидного
хода появляется одна плитка в случайной свободной клетке, увеличивается счётчик
ходов и обновляется score. Игра заканчивается после достижения `movesLimit`, а не
при появлении плитки `32%`. `32%` — максимальный уровень модели; две такие плитки
пока не объединяются в новый уровень.

Для воспроизводимого появления плиток создавай движок с конфигом и seed. Пока
уровень новой плитки берётся из первого элемента `spawnRules`; вероятности будут
учитываться в MR3. Конструктор без аргументов использует уровень `1` и обычный
генератор случайных чисел.

`./gradlew run` пока показывает начальное поле. Движок ходов доступен как Java API;
интерактивный ввод ходов через консоль не входит в текущую реализацию.
